# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health` (L72-74) | Always returns `{"status": "ok"}` — never pings MongoDB. If the DB is down the endpoint still returns 200 instead of 503. | Start the app without MongoDB running; `/health` returns 200. | Added `client.admin.command("ping")` in a try/except; raise `HTTPException(503)` on failure. |
| 2 | `create_employee` (L79) | Uses check-then-insert (`find_one` then `insert_one`). Two concurrent requests for the same `emp_code` can both pass the check and both insert, violating the uniqueness requirement. | Fire two parallel POST requests with the same `emp_code`; both may return 201. | Removed the `find_one` check. Relied on the unique index on `emp_code` and catch `DuplicateKeyError` → 409. |
| 3 | `create_employee` (L82) | `datetime.now()` is timezone-naive. MongoDB stores a naive datetime, and downstream epoch-millisecond conversion produces wrong values. | Compare `created_at` with a known UTC instant; it will be offset by the server's local timezone. | Changed to `datetime.now(tz=timezone.utc)`. |
| 4 | `create_employee` (L85) | Returns the raw MongoDB document. `created_at` is a datetime object (serialised by FastAPI as an ISO string), not an integer epoch-millisecond as the contract requires. `_id` is an ObjectId which would crash JSON serialisation. | Call `POST /employees`; the response contains `"created_at": "2026-..."` instead of `1783...`. | Built an explicit response dict converting `created_at` to epoch ms via `datetime_to_epoch_ms()` and omitting `_id`. |
| 5 | `create_employee` (L78) | No input validation. `emp_code` can be any string (contract requires `^EMP\d{4,6}$`). `email` format is not checked. `shift_start == shift_end` is accepted. `joined_on` is not validated as a date. | Post `{"emp_code": "X", "name": "A", "email": "bad", ...}` — 201 instead of 422. | Used Pydantic `Field` with `pattern`, `min_length`, `max_length` validators and added explicit check for `shift_start != shift_end`. |
| 6 | `list_employees` (L93) | `skip = page * page_size` — off by one. Page 1 skips `page_size` items, so the first page is empty (or shows page 2's data). | `GET /employees?page=1` with fewer employees than `page_size` returns an empty list. | Changed to `skip = (page - 1) * page_size`. |
| 7 | `list_employees` (L94) | `total = db.employees.count_documents({})` uses an empty filter, ignoring the `department` query. When filtering by department, `total` is wrong. | `GET /employees?department=Sales` reports `total: 100` even if Sales has only 3. | Changed to `db.employees.count_documents(query)` using the same filter. |
| 8 | `list_employees` (L95) | Returns `created_at` as a raw datetime (ISO string in JSON), not epoch milliseconds. | Response shows `"created_at": "2026-01-05T04:30:00"` instead of an integer. | Used `employee_doc_to_response()` converter. |
| 9 | `list_employees` (L88-96) | No sorting. The contract requires `emp_code` ascending. | Add employees in random order; they come back unsorted. | Added `.sort("emp_code", ASCENDING)`. |
| 10 | `punch_in` (L101) | No `404` when the employee does not exist. `emp` is `None`, and `emp["shift_start"]` on L113 raises `TypeError`, which FastAPI returns as 500. | `POST /attendance/punch-in {"emp_code": "EMP9999"}` → 500 Internal Server Error. | Added `if not emp: raise HTTPException(404, ...)` before using `emp`. |
| 11 | `punch_in` (L102) | `datetime.fromtimestamp(body.punched_at / 1000)` produces a **naive** datetime in the server's **local** timezone. This is wrong on any machine not set to UTC. Also, no validation that `punched_at` is a valid epoch-millisecond (not seconds, not negative). | Run on a machine in IST: the stored datetime is 5:30 h off. Pass `punched_at: 1000` (seconds-scale) — accepted without error. | Used `epoch_ms_to_datetime()` which creates a UTC-aware datetime. Added `validate_epoch_ms()` to reject bad values. |
| 12 | `punch_in` (L103) | `ts.date().isoformat()` uses the **local** timezone to determine the date, not IST. Also completely ignores the overnight-shift rule (R1). | An overnight-shift employee punching in at 03:00 IST gets the wrong date. | Used `determine_attendance_date()` which converts to IST and handles overnight shifts. |
| 13 | `punch_in` (L104-105) | Race condition: check-then-insert for duplicate detection. Two concurrent requests can both pass the `find_one` check and both insert, creating two records for the same `(emp_code, date)`. | Fire two concurrent punch-ins with the same `emp_code` and overlapping date → both return 201. | Removed the check. Used the compound unique index on `(emp_code, date)` and catch `DuplicateKeyError` → 409. |
| 14 | `punch_in` (L109) | `body.status` is accepted without validation. `ABSENT`, `LEAVE`, or any string is allowed. The contract requires only `PRESENT`, `WFH`, `ON_DUTY`. | `POST /attendance/punch-in {"emp_code":"EMP0001","status":"ABSENT"}` → 201. | Added validation: `if body.status not in PRESENCE_STATUSES: raise HTTPException(422, ...)`. |
| 15 | `punch_in` (L119) | Returns `doc["id"] = str(res.inserted_id)`. The `id` field does not exist in the contract and `_id` should never appear. Also, datetimes are not converted to epoch ms. | Response contains `"id": "664..."` and `"punch_in": "2026-07-06T..."` — neither matches the contract. | Used `attendance_doc_to_response()` which omits `_id` and converts all datetimes to epoch ms. |
| 16 | `punch_in` (L102) | No truncation of the instant to whole seconds (R1: "instants are truncated to whole seconds"). | Pass `punched_at` for 09:40:00.900 — stored as 09:40:00.900 and `late_minutes` could differ. | `epoch_ms_to_datetime` truncates `ms // 1000 * 1000` (drops sub-second). |
| 17 | `compute_late_minutes` (L35-37) | `punch_in.replace(hour=h, minute=m)` builds shift-start from punch_in's date and timezone. For overnight shifts, punch_in can be on a different day than the shift start. Also, the result can be negative (early arrival) and is returned as-is. | An overnight-shift punch-in at 22:05 on day D: `replace(hour=22,...)` might work, but a punch at 03:00 on day D+1: `replace(hour=22,...)` gives shift_start on the wrong day → negative or huge value. | Rewrote to build shift-start on the **attendance date** in IST, convert to UTC, then diff. Returns 0 for negative diff. Uses `diff_seconds // 60` per R2. |
| 18 | `compute_work_hours` (L40-41) | Python's `round()` uses **banker's rounding** (round half to even). R4 requires **half-up** rounding. | `round(8.415, 2)` → `8.41` (rounds down), but half-up gives `8.42`. | Used `Decimal.quantize(ROUND_HALF_UP)` via the `round_half_up()` helper. |
| 19 | `compute_overtime` (L44-47) | Missing the 30-minute minimum threshold (R3: overtime counts only when >= 30 minutes; otherwise 0). Also returns negative values (punch-out before shift-end). For overnight shifts, builds shift_end on the wrong day. | Punch out 10 min after shift_end → `overtime_minutes: 10` instead of `0`. | Rewrote: returns 0 if diff < 0 or floor-minutes < 30. For overnight shifts, adds 1 day to the end-time. |
| 20 | `list_attendance` (L144) | `list(db.attendance_logs.find(q))` loads the **entire** filtered result set into Python memory, then sorts and paginates in Python. At 100k records this is slow and uses excessive memory. | Load 100k records; the endpoint takes seconds and the process uses hundreds of MB. | Changed to database-side sort+skip+limit with proper indexes: `.sort(...).skip(...).limit(...)`. |
| 21 | `list_attendance` (L149) | Adds `d["id"] = str(d.pop("_id"))` — the `id` field is not in the contract. Datetimes inside the record are not converted to epoch ms. | Response contains `"id"` and `"punch_in": "2026-..."`. | Used `attendance_doc_to_response()` and projected out `_id` in the query. |
| 22 | `list_attendance` (L145) | Sorts only by `date` descending. The contract requires date descending, **then `emp_code` ascending**. | Two records on the same date come back in arbitrary order. | Changed sort to `[("date", DESCENDING), ("emp_code", ASCENDING)]`. |
| 23 | `list_attendance` (L129-132) | No validation that `date_from <= date_to`. The contract says `date_from > date_to → 422`. | `GET /attendance?date_from=2026-08-01&date_to=2026-07-01` returns 200 with empty results instead of 422. | Added `if date_from and date_to and date_from > date_to: raise HTTPException(422, ...)`. |

## Not a defect

| # | Where | Why it's fine |
|---|---|---|
| 1 | `load_dotenv()` at module level | Acceptable for local development convenience. Real env vars override `.env` values. |
| 2 | `IST = timezone(timedelta(hours=5, minutes=30))` | Correct representation of IST as a fixed UTC offset. IST does not observe DST. |
| 3 | `MongoClient` at module level | Standard pattern for FastAPI. The client is thread-safe and connection-pooled. |
